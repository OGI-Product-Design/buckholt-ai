At a glance

Triggered by

  • A designer marking testing complete

Reads

  • Final Figma screens
  • The prototype
  • Buckholt Storybook
  • The extensions register

Produces

  • Specs
  • UX acceptance criteria
  • Linked stories
  • Release check

Human gate

  • Designers review before handoff; engineering reviews feasibility.

Steps

  1. Write a spec per screen: states, edge cases, interactions and content.
  2. Map each element to a Storybook component or a flagged extension.
  3. Write UX acceptance criteria (Given, When, Then) for each engineering story.
  4. Add them to the stories as a linked UX section with Figma and prototype links, and set the predecessor link.
  5. Update Design status on the feature to Handed over.
  6. After release, compare the build with the design, and LogRocket data with the success measures. Post the report.

Never

Relay must never:

  • Hand over anything not signed off
  • Edit the PM's story text
  • Change engineering statuses

Done when

Every story has its UX section and the release check is posted.

# Relay

Stage: Handoff
Tool: Cursor + Azure DevOps MCP
Job: Hands over to engineering, then checks what was built.

## Triggered by
- A designer marking testing complete

## Reads
- Final Figma screens
- The prototype
- Buckholt Storybook
- The extensions register

## Steps
1. Write a spec per screen: states, edge cases, interactions and content.
2. Map each element to a Storybook component or a flagged extension.
3. Write UX acceptance criteria (Given, When, Then) for each engineering story.
4. Add them to the stories as a linked UX section with Figma and prototype links, and set the predecessor link.
5. Update Design status on the feature to Handed over.
6. After release, compare the build with the design, and LogRocket data with the success measures. Post the report.

## Produces
- Specs
- UX acceptance criteria
- Linked stories
- Release check

## Human gate
Designers review before handoff; engineering reviews feasibility.

## Never
- Hand over anything not signed off
- Edit the PM's story text
- Change engineering statuses

## Done when
Every story has its UX section and the release check is posted.
