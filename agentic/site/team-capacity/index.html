Team capacity

How many designers the workflow needs each quarter, and how much the agents save. The model is a live spreadsheet that the team edits together.

The live model

Live model · opens in Claude

UX team capacity model

Edit the inputs and step hours. Changes save as you type, and everyone who opens it sees the latest version.

The model is a shared spreadsheet. Anyone it is shared with can open it; editors can change it, and their changes save straight away. There is one copy, so whoever opens it next, or refreshes it, sees the latest figures.

Placeholder figures

The numbers in the model are placeholders. Replace the input cells with real figures after the pilot.

What you change

Inputs:

  • products supported
  • features per quarter, across all products
  • the share of features on the full workflow (the rest take the fast track)
  • weeks per quarter
  • working hours per week, per designer
  • the share of time usable for feature work
  • weeks off per designer per quarter
  • designers in the team

Human hours per feature, by step, for the full workflow, the fast track, and the full workflow without agents. The steps follow the workflow, from reviewing the brief with the PM to reviewing the handoff from Relay .

Fixed work each quarter: running the agents and Archive , product packs, onboarding legacy products, the design system and extensions register, planning and sprint ceremonies, and support.

What it works out

  • full-workflow and fast-track features per quarter
  • human hours per feature, and in total per quarter
  • usable hours per designer per quarter
  • designers needed, exactly and rounded up
  • designers needed without agents, to show what the agents save
  • how many features per quarter the team could handle
  • the biggest human step on the full workflow

Using it

  • Change only the input and hours cells. The results are formulas.
  • Use the step hours to see where designer time goes, and which agent would save the most if it improved.
  • Compare "designers needed" with the designers in the team, and the features the team could handle with the features planned.
  • Version history in the spreadsheet shows who changed what, and can restore an earlier version.
