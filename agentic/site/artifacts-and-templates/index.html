Artifacts and templates

Seven artifacts carry the work between agents. Each has one writer, one home, and named readers.

The seven artifacts

Artifact
Written by
Where it lives
Read by
Product pack Archive , with Laurence's approval Repo /context, copy in SharePoint All agents
UX brief Brief SharePoint, linked on the design item Insight , Map , the PM
Discovery summary Insight and Map SharePoint, summary copy in the repo Range , Critic , Build , Observe
Decision log Archive , from gate outcomes Repo /context All agents, Jim, PMs
Extensions register Extend and Build Repo /context Align , Audit , Relay
Migration map Archive Repo /context Build , Align
Agent definition Laurence Repo /agents The agent itself

Where each one comes from

  • Product pack: one per product, including its styling mode. A change is merged in the repo, then Archive updates the SharePoint copy. Laurence or Jon approves every change.
  • UX brief: Brief writes it from the template once the feature has everything it needs, and links it on the design item.
  • Discovery summary: Insight lists every source, anonymises personal details and groups findings into themes with evidence. On Discovery approved, Archive writes the repo copy to /context/discovery/[feature].md.
  • Decision log: after each gate, Archive adds the decision to decision-log.md from the gate notes.
  • Extensions register: one entry per extension, with a Figma half and a code half.
  • Agent definition: one file per agent in /agents, changed by pull request.

Templates

The agents work from shared templates. Each one below follows what the agent's rules say it must contain. Copy a template to use it.

UX brief

Written by Brief , saved to SharePoint and linked on the design item.

UX brief template 
# UX brief: [feature name]

Design item: [link]   Feature: [link]   Date: [date]

## Problem
[The user problem, in one or two sentences.]

## Outcome
[What changes for users and the business when this is done.]

## Products and styling mode
- [Product]: [Buckholt, Hybrid or Legacy]

## Users
[Who this is for.]

## Priority and quarter
[Priority] · [Quarter]

## Constraints
- [Constraint]

## Route
[Full or Fast track]
Why: [No new flow? No new research needed? Only existing screens change?]

## Success measures
| Measure | Baseline (from Insight) | Target |
|---|---|---|
| Completion | [to request] | [target] |
| Drop-off | [to request] | [target] |
| Errors | [to request] | [target] |

## Scope confirmed by the PM
[Name, date]

Discovery summary

Written by Insight , saved to SharePoint, then copied into the repo by Archive .

Discovery summary template 
# Discovery summary: [feature name]

## Sources
- [SRC-01] [Source, link, date]

## Themes
### [Theme]
Evidence: [SRC-01, SRC-02]   Products: [product]
[What we found.]

## Pain points, ranked
| Pain point | How often | How badly | Evidence |
|---|---|---|---|

## Baselines (LogRocket)
| Flow | Completion | Drop-off | Errors | Rage clicks |
|---|---|---|---|---|

## Evidence gaps
- [Gap]: [research that would fill it]

All personal data removed: [yes]

Critique

Written by Critic as critique.md in the sandbox feature folder.

Critique template 
# Critique: [feature name]

## Direction [n]: [name]
- User needs served: [themes]
- User needs missed: [themes]
- Edge cases: empty [ ] error [ ] loading [ ] permissions [ ] heavy data [ ] long text [ ]
- Consistency with product patterns and styling mode: [notes]
- Build effort: [low, medium or high], because [reason]
- Risks: [risks]

## Recommendation (for the shortlist gate to decide)
1. [Direction], because [reason]
