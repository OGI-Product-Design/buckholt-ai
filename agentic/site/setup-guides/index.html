Set-up guides

Set up the foundations first, then connectors and access, then the agents. Each guide builds on the one before.

The order

  1. Foundations: the repo and its locks, product packs, the design board and the SharePoint site.
  2. Connectors and access: Figma MCP (write for Extend , read and Code Connect for the others), LogRocket MCP, Lucid MCP, the Azure DevOps connector and the legacy Figma libraries.
  3. Agents: create the nine Cursor agents and the three Microsoft 365 Copilot agents (guides 10 and 11).

The guides

Guide 1 of 11

Repo and locks

Agents can only be trusted with the repo if the folders they must never change are locked.
Guide 2 of 11

Product packs

Every agent reads the product pack, so each product needs one before any feature for it can start.
Guide 3 of 11

Design board

The design board runs the workflow. Its stage statuses are what start each agent.
Guide 4 of 11

SharePoint site

SharePoint holds the discovery master copy and a copy of every product pack, so people outside Cursor can read them.
Guide 5 of 11

Figma MCP

Figma MCP lets agents read the designs, and lets one agent, Extend, build them out.
Guide 6 of 11

Legacy Figma libraries

Products not yet on Buckholt need their own Figma library, so anchors and extended screens match how the product looks today.
Guide 7 of 11

LogRocket MCP

LogRocket gives every feature real baselines, so success measures are based on what users actually do.
Guide 8 of 11

Lucid

Lucid holds the journey maps from Discover and the rough flows from Explore.
Guide 9 of 11

Azure DevOps connectors

Agents read features and write to stories through Azure DevOps, so the work and the record stay in one place.
Guide 10 of 11

Create agents in Cursor

Nine of the twelve agents run in Cursor. Each one is a rules file that points Cursor's Agent at that agent's definition.
Guide 11 of 11

Create agents in Microsoft 365 Copilot

Brief, Insight and Map run in Microsoft 365 Copilot, close to the SharePoint, Teams and Azure DevOps content they read.

Adding a guide

Each guide is a Markdown file in agentic/content/guides/setup-guides/, named with its position, for example 03-figma-mcp.md. The site numbers them, shows progress and links each one to the next.

Guide file template 
---
title: Connect Figma MCP
lead: One sentence on why this matters.
---
