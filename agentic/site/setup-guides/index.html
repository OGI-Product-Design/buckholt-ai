Set-up guides

Set up the foundations first, then connectors and access, then the agents. Each guide builds on the one before.

The order

  1. Foundations: the repo and its locks, product packs, the design board and the SharePoint site.
  2. Connectors and access: Figma MCP (write for Extend , read and Code Connect for the others), LogRocket MCP, Lucid MCP, the Azure DevOps connector and the legacy Figma libraries.
  3. Agents, by stage.

The guides

  1. Repo and locks: agents can only be trusted with the repo if the folders they must never change are locked.
  2. Product packs: every agent reads the product pack, so each product needs one before any feature for it can start.
  3. Design board: the design board runs the workflow. Its stage statuses are what start each agent.
  4. SharePoint site: sharePoint holds the discovery master copy and a copy of every product pack, so people outside Cursor can read them.
  5. Figma MCP: figma MCP lets agents read the designs, and lets one agent, Extend, build them out.
  6. Legacy Figma libraries: products not yet on Buckholt need their own Figma library, so anchors and extended screens match how the product looks today.
  7. LogRocket MCP: logRocket gives every feature real baselines, so success measures are based on what users actually do.
  8. Lucid: lucid holds the journey maps from Discover and the rough flows from Explore.
  9. Azure DevOps connectors: agents read features and write to stories through Azure DevOps, so the work and the record stay in one place.

Adding a guide

Each guide is a Markdown file in agentic/content/guides/setup-guides/, named with its position, for example 03-figma-mcp.md. The site numbers them, shows progress and links each one to the next.

Guide file template 
---
title: Connect Figma MCP
lead: One sentence on why this matters.
---
