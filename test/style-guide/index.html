Buckholt style guide

A visual catalogue of the Buckholt design system: the foundations first, then every documented component grouped by what it does. Everything on this page is real Buckholt markup rendered by css/buckholt.css — nothing here recreates, overrides or imitates Buckholt styling.

Components are composed from the canonical markup in components/<name>/examples.html. Where a documented example deliberately elides content, this page completes it using verified markup from the same component so the variant can actually be seen; the canonical source keeps its elision untouched. Identifiers are made unique to this page so labels and ARIA wiring resolve correctly when every example shares one document.

Styles load in the verified order: the Typekit stylesheet for Proxima Soft, the Buckholt Font Awesome kit, then css/buckholt.css, then css/buckholt-ai-fixes.css. There is no separate Bootstrap stylesheet — buckholt.css is itself a complete Bootstrap 5.3 build with Buckholt as the theme, and the live Buckholt documentation site loads only its own compiled CSS. Behaviour still comes from the Bootstrap bundle, jQuery and the Buckholt component scripts — a separate dependency the live site also loads, active, at 5.1.3.

This is the reference view. Source and runtime evidence — verification status, classified discrepancies and the exact unmodified canonical markup — lives in test/runtime-verification/ and discrepancies/known-issues.md.

Expressive

Expressive colours add tone, personality and emphasis beyond the core functional roles. They support the interface rather than carrying meaning, so they must not be substituted for semantic action or feedback roles just because they look similar.

There are four families. Primary is the default and needs no class; the other three are selected with .expressive-secondary, .expressive-tertiary and .expressive-quaternary, which remap the unprefixed --expressive-* variables. That indirection is why a component such as Icon block can consume var(--expressive-deep) and pick up whichever family is active.

Shadows

Elevation for genuinely raised UI only — dialogs and other high layers take the heavier steps, tooltips and toasts the lighter ones. Do not add elevation decoratively to flat content.

--shadow-xs · .shadow-xs
--shadow-sm · .shadow-sm
--shadow-md · .shadow-md
--shadow-lg · .shadow-lg
--shadow-xl · .shadow-xl

Buckholt also swaps the shadow colour for feedback states through .shadow-info, .shadow-success, .shadow-warning and .shadow-error. Use those only where the matching feedback pattern calls for them.

Iconography

All 111 documented icons from foundations/iconography/catalogue.md, grouped by category. This doubles as a check that the Font Awesome kit is loading — a blank tile means the kit failed or the mapping is wrong.

The catalogue is authoritative for icon choice. Match the documented role to the intended action, use the exact classes recorded here, and preserve the deliberate solid and brands entries rather than converting everything to regular.

Alert

Inline feedback tied to the surrounding content. The colour and the left bar come from a status modifier — .alert-info, .alert-success, .alert-warning or .alert-error. A bare .alert is deliberately transparent: it defines the anatomy and leaves the status to say what it means. The anatomy examples below carry .alert-info so the shape is visible.

Buckholt documents the close control in two places: as a sibling of .alert-content / .toast-content, and inside it. Only the sibling placement is supported by the CSS — the wrapper claims width: 100% and pushes the button to the trailing edge, and its 32px box matches the content row exactly, so the label stays vertically centred. Placed inside, the button becomes a third item in a 24px row: the row grows to 32px and the label sits 4px high. These compositions therefore use the sibling placement. Both documented placements are kept verbatim in test/runtime-verification/, where the difference is measured. See discrepancies/known-issues.md.
