Buckholt style guide

A single page rendering every foundation and component this repository documents, styled entirely by css/buckholt.css. It exists so drift is visible in one place: open it after a runtime or documentation change and check the whole system at once.

Everything here is built from the repository sources — foundations/ for the scales and tokens, components/<name>/rules.md for behaviour and components/<name>/examples.html for canonical markup. Nothing is invented, and no Buckholt styling is recreated or overridden. The page's own stylesheet holds layout only, using Buckholt tokens for every value.

Dependencies load in the order given in CLAUDE.md: Bootstrap 5.1.3, the Typekit stylesheet for Proxima Soft, the Buckholt Font Awesome kit, then css/buckholt.css, then css/buckholt-ai-fixes.css for the verified compatibility corrections. The Bootstrap JavaScript bundle loads at the end of the page for the documented icon-only button tooltips; it ships no CSS, so it cannot affect the cascade.

Known differences between the documentation and the runtime are recorded in discrepancies/known-issues.md, which stays the canonical record. They are surfaced beside the affected component and collected again at the foot of this page.

Expressive

Expressive colours add tone, personality and emphasis beyond the core functional roles. They support the interface rather than carrying meaning, so they must not be substituted for semantic action or feedback roles just because they look similar.

There are four families. Primary is the default and needs no class; the other three are selected with .expressive-secondary, .expressive-tertiary and .expressive-quaternary, which remap the unprefixed --expressive-* variables. That indirection is why a component such as Icon block can consume var(--expressive-deep) and pick up whichever family is active.

Gap — the foundation notes only three families

foundations/colour/foundation-tokens.md states that "the runtime includes primary, secondary and tertiary expressive families". The runtime defines four, and components/icon-block/examples.html documents .expressive-quaternary as a supported treatment. The foundation text undercounts the palette, and gives no table for these roles at all, which is why they were missing from this page until now.

Contrast targets from the Colour documentation: 4.5:1 for text below 24px, 3:1 for text at 24px and above, and 3:1 for icons and other visual elements. Colour must never be the only way meaning is communicated.

Button

Buttons trigger actions; links navigate. Buckholt documents three types — primary for the principal action, secondary for supporting actions, ghost for supplementary and opposing actions such as Cancel. Danger is a modifier layered on any of them, not a fourth type.

Types and the danger modifier

Standard
With .btn-danger
<button type="button" class="btn btn-primary"> <span class="button-label">Save changes</span> </button>

Known issue — the error status icon renders black, not red

Compare the two status icons above: success is green, but error is black. The documentation site shows it in the error colour. The success icon encodes its fill as a literal value, while the error icon tries to use a custom property:

fill='%23168914' for success, against fill='var%28--error-01%29' for error.

A data: URI is a separate document, so custom properties from the host page do not cascade into it. var(--error-01) is not a resolvable paint value there and the fill falls back to black. Encoding the literal %23d7050c, exactly as the success icon does, renders it correctly. Recorded in discrepancies/known-issues.md; not patched here.

Fixed in this repository's runtime — action set no longer wraps

The two tiles above wrap their buttons in a .button-set, which is the pattern that produces Buckholt's documented 4px icon-only spacing. Until recently that set collapsed and wrapped onto two lines.

The cause was in css/buckholt.css, not in the documented markup: .versatile-body declares width: 100% while .versatile-actions set no flex-shrink, so the actions column was squeezed. Because .button-set carries flex-wrap: wrap, its min-content width is a single 40px button, so it collapsed to 76px where 84px was needed.

flex-shrink: 0 has been added to .versatile-actions in css/buckholt.css. The set now renders 84px wide with a 4px gap on one row, at every viewport width tested, and long labels still truncate rather than pushing the actions out. This change must be carried into the upstream Buckholt build, or the next compiled stylesheet drop will reintroduce the bug — see discrepancies/known-issues.md.

Button focus falls through to Bootstrap after a mouse click

Buckholt styles the Button focus state only through :focus-visible, while Bootstrap 5.1.3 styles plain :focus for the button classes Buckholt reuses. A mouse click sets :focus but deliberately not :focus-visible, so Bootstrap's colours apply unopposed — secondary renders grey #5c636a with a white label. Primary, ghost and the danger combinations are affected too. Keyboard focus is correct. Fix belongs in css/buckholt.css.

Link visited state is not implemented

The documentation defines a visited state of #5731d6 for link text and icon. The runtime contains no :visited rule, so visited links are indistinguishable from unvisited ones, and --link-visited / --link-icon-visited are set to #1748d0 rather than the documented colour.

Summary Meta uses an inert expressive-primary class

components/summary-meta/rules.md and its examples.html both write expressive-dark expressive-primary, but no .expressive-primary rule exists. Primary is the root default and only secondary, tertiary and quaternary have modifiers, so the class does nothing. Rendering is correct; the markup is misleading.

Progress bar error status icon renders black

The error status icon encodes its fill as fill='var%28--error-01%29' inside a data: URI SVG. Custom properties do not cascade into a data URI, so the fill falls back to black instead of #d7050c. The success icon uses a literal %23168914 and renders correctly.

Versa-tile icon-only action set wrapped — fixed here, needs upstreaming

A .button-set inside .versatile-actions — the pattern that gives the documented 4px icon-only spacing — collapsed to 76px and wrapped, because .versatile-body claims width: 100% while .versatile-actions set no flex-shrink. flex-shrink: 0 has been added to .versatile-actions in this repository's css/buckholt.css. Radius full name and value disagree

The documentation defines full as 2rem / 32px. The runtime --border-radius-full is 625rem, with 2rem exposed as --border-radius-xxl. Do not remap one name to the other while this stands.
