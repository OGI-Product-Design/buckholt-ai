Buckholt style guide

A single page rendering every foundation and component this repository documents, styled entirely by css/buckholt.css. It exists so drift is visible in one place: open it after a runtime or documentation change and check the whole system at once.

Everything here is built from the repository sources — foundations/ for the scales and tokens, components/<name>/rules.md for behaviour and components/<name>/examples.html for canonical markup. Nothing is invented, and no Buckholt styling is recreated or overridden. The page's own stylesheet holds layout only, using Buckholt tokens for every value.

Dependencies load in the order given in CLAUDE.md: Bootstrap 5.1.3, the Typekit stylesheet for Proxima Soft, the Buckholt Font Awesome kit, then css/buckholt.css last. The Bootstrap JavaScript bundle loads at the end of the page for the documented icon-only button tooltips.

Known differences between the documentation and the runtime are recorded in discrepancies/known-issues.md, which stays the canonical record. They are surfaced beside the affected component and collected again at the foot of this page.

Button

Buttons trigger actions; links navigate. Buckholt documents three types — primary for the principal action, secondary for supporting actions, ghost for supplementary and opposing actions such as Cancel. Danger is a modifier layered on any of them, not a fourth type.

Types and the danger modifier

Standard
With .btn-danger
<button type="button" class="btn btn-primary"> <span class="button-label">Save changes</span> </button>

.button-label is a structural hook as well as a wrapper — Buckholt uses its presence to tell labelled and icon-only layouts apart, so it must not be omitted.

Sizes

.btn-sm, no modifier, .btn-lg — 32px, 40px and 48px minimum height. Small suits confined layouts; large suits greater emphasis such as the end of a form.

Small
Default
Large

Labelled buttons with icons

A .btn-icon wrapper sits before .button-label. Buckholt trims 4px from the leading padding, and the icon inherits the label's colour and size. Icons are optional, sit to the left of the label, and must relate directly to the action.

Small / default / large
Across types
<button type="button" class="btn btn-primary"> <div class="btn-icon"> <i class="fa-regular fa-plus" aria-hidden="true"></i> </div> <span class="button-label">Create document</span> </button>

Icon-only buttons

An icon-only button is a .btn containing .btn-icon and no .button-label. That absence is the runtime trigger: Buckholt selects them with .btn:not(:has(.button-label)) and squares them to 40px, or 32px at .btn-sm. Default and small are the only documented icon-only sizes.

  • Use only where the icon is standardised and clearly recognisable, and use sparingly.
  • Prefer a toolbar pattern when several compact icon actions are needed.
  • Provide an accessible name, and a tooltip explaining the action is always required.

The accessible name uses aria-label, not .button-label, because adding that element would convert the control back to a labelled button. The documented trigger is hover only, so the tooltip does not appear on keyboard focus — the accessible name still does.

Disabled

The native disabled attribute — no aria-disabled substitute and no custom dimming. Buckholt keeps the resting colours at 65% opacity and removes interaction.

Button sets

Two or more related buttons go inside .button-set. Buckholt binds set layout to [class$=-set] / [class*="-set "] with [class|=button], so button-set must be the first class on the element — a utility class in front of it silently disables the set rules.

  • 8px spacing, and 8px row spacing when the set wraps.
  • Primary sits on the outer edge; secondary and ghost sit inside.
  • Never two high-emphasis buttons in one set.
  • Beyond three calls to action, prefer ghost over repeated secondary.
  • Do not mix icon-only and labelled controls in the same set.

Buckholt narrows the gap with [class|=button]:has(.btn-icon):not(:has(.button-label)), so 4px applies only when the set is entirely icon-only. That is the same rule enforcing "do not mix icon-only and labelled controls" — mixing them silently restores 8px.

States, focus and keyboard

Native buttons, so Enter and Space activate them. Tab through the row to see Buckholt's focus treatment. Resting primary and secondary carry a deliberate 3px bottom border (1px + 0.125rem) which returns to 1px on focus and active; ghost stays 1px.

Known issue — focus falls through to Bootstrap

Click any button above with a mouse, then move the pointer away. Buckholt styles focus only through :focus-visible, while Bootstrap styles plain :focus for the same class names. A mouse click sets :focus but not :focus-visible, so Bootstrap's colours win — most visibly on secondary, which turns grey. Keyboard focus is unaffected. Recorded in discrepancies/known-issues.md; the fix belongs in css/buckholt.css.

Link

Links navigate — to another page, a location on this page, an email address or a telephone number. Never use a link for an action that modifies data, changes state or alters the display; that is a Button. Links are intentionally lightweight, so avoid overusing them.

Inline link

A plain anchor with no Link-specific class, underlined so it stays distinguishable from surrounding text. Inline links should not be used in isolation and should never carry icons.

Standalone link

.link-standalone is used independently of paragraph text. It has no underline at rest; the underline appears on hover, focus and active. It may take an icon where that helps communicate navigation or distinguishes it from a nearby ghost button.

The external-link icon is used whenever a link opens a new tab, whether the destination is inside the product or outside it. The icon is supplementary — the label and surrounding context must make the destination clear on their own.

States

Hover, focus and active are supplied by Buckholt — hover and active add the underline to a standalone link, and active text and icon use Text primary (#1a1a1a). Tab into the links above to check the keyboard focus treatment.

Known issue — visited state is not implemented

The Link documentation defines a visited state of Expressive secondary deep (#5731d6) for both link text and icon. The current runtime contains no :visited rule at all, so visited links render exactly like unvisited ones. The tokens that would drive it, --link-visited and --link-icon-visited, are both set to #1748d0 rather than the documented colour, and nothing consumes them. Recorded in discrepancies/known-issues.md.

Text block

Buckholt's written-content component. .text-block manages text width and the spacing between headings and paragraphs, so that spacing should never be recreated locally. A Text block must contain at least a heading, a paragraph, or both.

Heading level and heading style are separate decisions: pick the semantic h1– h6 from page hierarchy, then pick the visual class from the type sets. Never skip a level to obtain a size.

Known runtime issues

Differences between the documented Buckholt behaviour and what the runtime renders. This is a reading view — discrepancies/known-issues.md stays the canonical record, and new findings should be added there first. None of them is worked around on this page.

Button focus falls through to Bootstrap after a mouse click

Buckholt styles the Button focus state only through :focus-visible, while Bootstrap 5.1.3 styles plain :focus for the button classes Buckholt reuses. A mouse click sets :focus but deliberately not :focus-visible, so Bootstrap's colours apply unopposed — secondary renders grey #5c636a with a white label. Primary, ghost and the danger combinations are affected too. Keyboard focus is correct. Fix belongs in css/buckholt.css.

Link visited state is not implemented

The documentation defines a visited state of #5731d6 for link text and icon. The runtime contains no :visited rule, so visited links are indistinguishable from unvisited ones, and --link-visited / --link-icon-visited are set to #1748d0 rather than the documented colour.

Radius full name and value disagree

The documentation defines full as 2rem / 32px. The runtime --border-radius-full is 625rem, with 2rem exposed as --border-radius-xxl. Do not remap one name to the other while this stands.
