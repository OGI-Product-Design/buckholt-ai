Buckholt Button showcase

Every control on this page is styled entirely by css/buckholt.css, using the markup verified in components/button/examples.html and the guidance in components/button/rules.md. The page stylesheet contains showcase layout only — no Buckholt button styling is recreated or overridden anywhere.

Runtime dependencies are loaded in the order given in CLAUDE.md: Bootstrap 5.1.3, the Adobe Fonts (Typekit) stylesheet for Proxima, the Buckholt Font Awesome kit, and then css/buckholt.css last so Buckholt supplies the final component styling.

1. Button types

Buckholt documents three types. Primary is the highest emphasis and is normally used once per screen or contained context; secondary is medium emphasis for supporting actions; ghost is the lowest emphasis, for supplementary and opposing actions such as Cancel.

2. Danger modifier

Danger is a modifier, not a fourth type. .btn-danger is added alongside a standard type and the compiled CSS pairs it with each one (.btn-primary.btn-danger, .btn-secondary.btn-danger, .btn-ghost.btn-danger). Use it for destructive actions.

Secondary + danger

3. Sizes

.btn-sm for small, no modifier for default/medium, .btn-lg for large. Small suits confined layouts, large suits greater emphasis such as the end of a form. Runtime minimum heights are 32px, 40px and 48px.

4. Labelled buttons with icons

The verified structure places a .btn-icon wrapper before .button-label. Buckholt trims 4px from the leading padding when an icon is the first child of a labelled button, and the icon inherits the label's colour and font size.

  • Icons are optional and should be used sparingly.
  • Icons sit to the left of the label — never after it.
  • The icon must relate directly to the action; do not repurpose a familiar icon.
  • Keep icon usage consistent across comparable labelled buttons in the same set.

Icon choice is constrained by the evidence in this repository. examples.html verifies exactly one Font Awesome class pair, fa-regular fa-ghost. rules.md names the recognisable actions Buckholt documents — Add, Copy, Delete, Download, Edit, External link, Logout, Save, Search, Settings and Upload — but records no Font Awesome class for any of them. Rather than guess fa-plus, fa-trash and so on, every icon slot below uses the one verified glyph as a placeholder.

5. Icon-only buttons

An icon-only button is a .btn containing .btn-icon and no .button-label. That absence is the actual runtime trigger: Buckholt selects icon-only buttons with .btn:not(:has(.button-label)) and squares them to 40px by default and 32px at .btn-sm. Adding a .button-label back would silently turn the control into a normal labelled button.

  • Documented sizes are default/medium and small only — there is no documented large icon-only button, so none is shown.
  • Primary, secondary and ghost may all be used; primary and ghost are the common choices.
  • Use only where the icon is standardised and clearly recognisable, and use sparingly.
  • Prefer a toolbar pattern when several compact icon actions are needed.
  • Every icon-only button must have an accessible text name and a visible tooltip.

Accessibility treatment used here. The accessible name is real text inside the button, hidden visually with .visually-hidden — this keeps the name in the accessibility tree without adding a .button-label, which would change the button's runtime sizing. The visible tooltip comes from the native title attribute. Buckholt's compiled CSS carries Bootstrap's .tooltip styles, but those need Bootstrap's JavaScript bundle, which is not part of the approved runtime setup in CLAUDE.md, so no Buckholt-styled tooltip is claimed here.

The names below read "Example action" deliberately. With only the ghost glyph verified, pairing it with a specific label such as "Delete" would repurpose a familiar icon for an unrelated action, which rules.md forbids. In production the name and tooltip must describe the real action.

7. Button sets

Two or more related buttons go inside .button-set. Buckholt binds set layout to the attribute selectors [class$=-set] and [class*="-set "] combined with [class|=button], so button-set must be the first class on the element — putting a utility class in front of it silently disables the set rules.

  • Default spacing is 8px, with 8px row spacing when the set wraps.
  • The primary button sits on the outer edge; secondary and ghost sit inside.
  • Group only contextually related actions, and never use two high-emphasis buttons in one set.
  • With more than three calls to action, ghost buttons are preferable to several secondary buttons.
  • Do not mix icon-only and labelled controls in the same set.
Standard set — full-page layout, primary on the left/outer edge
More than three actions — ghost preferred over repeated secondary
Icon-only set — spacing tightens to 4px automatically

Buckholt narrows the gap with [class|=button]:has(.btn-icon):not(:has(.button-label)), so the 4px spacing applies only when the set is entirely icon-only. This is the same rule that enforces "do not mix icon-only and labelled controls in one set" — mixing them silently restores 8px spacing.

Contained layout — primary on the right/outer edge

8. Stacked / full-width button sets

Adding .button-set-stacked switches the set to a column and stretches every direct child button to full width. Row spacing stays at 8px. Short forms and small screens are the documented cases for full-width buttons.

9. Focus, keyboard and states

These are native <button> elements, so they are keyboard operable and activate with Enter or Space. Tab through the page to see Buckholt's own focus treatment; hover and active styling come from the same stylesheet. No state colour is hard-coded on this page.

One runtime detail worth knowing when inspecting focus: Buckholt gives resting primary and secondary buttons a thicker bottom border (--button-border-bottom-width: calc(1px + 0.125rem), i.e. 3px) and resets it to 1px on focus and active. Ghost buttons are 1px throughout. See the findings table below.

10. Findings

Conflicts and gaps found between the documentation files and the compiled stylesheet, reported rather than patched. Nothing below has been worked around with custom CSS.

Finding Detail
CLAUDE.md and README.md are out of date Both state that "the canonical danger modifier and exact icon markup remain unresolved … Do not guess them". components/button/rules.md and components/button/examples.html now document both, and css/buckholt.css implements .btn-danger for all three types. The component files and the stylesheet agree, so this page follows them; the two top-level files need updating.
The 3px bottom border is in the runtime after all rules.md says "Do not recreate the previously interpreted 3px bottom-border treatment. It is not the current compiled runtime implementation." The compiled CSS does implement it: --button-border-bottom-width: calc(1px + 0.125rem) applied via border-bottom-width, reset to 1px for ghost and on focus/active. Primary and secondary buttons on this page therefore render with a 3px bottom border straight from Buckholt. The stylesheet is the styling source of truth, so nothing was overridden — but the sentence in rules.md is wrong.
Font Awesome class names are not recorded rules.md lists the recognisable actions Buckholt documents but gives no Font Awesome class for any of them, and examples.html verifies only fa-regular fa-ghost. That single glyph is used as a placeholder throughout rather than guessing class names.
No documented Buckholt tooltip rules.md requires a visible tooltip on every icon-only button but documents no tooltip markup. Buckholt's CSS carries Bootstrap's .tooltip styles, which need Bootstrap's JavaScript bundle — not part of the approved dependency list. The native title attribute is used instead.
.button-label has no styling of its own It carries no visual rules; it exists purely as a structural hook. Buckholt tests for its presence (:has(.button-label)) to decide whether a button is labelled or icon-only, so omitting it on a labelled button silently converts that button into a fixed 40px square.
<div> inside <button> The canonical icon markup nests a <div> inside a <button>, which is not valid HTML — buttons take phrasing content. The CSS selectors (.btn .btn-icon) would work equally well with a <span>. The documented markup is used here unchanged rather than silently improved, but the Buckholt source is worth correcting.
Set alignment classes are undocumented rules.md describes left- and right-aligned layouts but names no class. The compiled CSS provides -set-center, -set-end and -set-nowrap attribute matches; button-set-end is used once above and flagged inline as runtime-verified but undocumented.
