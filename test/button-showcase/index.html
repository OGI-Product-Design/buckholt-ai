Buckholt Button

Every control on this page is styled by css/buckholt.css, using the canonical markup in components/button/examples.html and the guidance in components/button/rules.md. Icons come from foundations/iconography/catalogue.md, and the page's own layout uses Buckholt spacing, colour and radius tokens rather than hard-coded values.

Dependencies load in the order given in CLAUDE.md — Bootstrap 5.1.3, the Typekit stylesheet for Proxima Soft, the Buckholt Font Awesome kit, then css/buckholt.css last. The Bootstrap JavaScript bundle is loaded at the end of the page because the documented icon-only tooltip pattern needs it.

1. Button types

Buckholt documents three types. Primary carries the highest emphasis and is normally used once per screen or contained context. Secondary is medium emphasis for supporting actions. Ghost is the lowest emphasis, for supplementary and opposing actions such as Cancel.

<button type="button" class="btn btn-primary"> <span class="button-label">Save changes</span> </button>

.button-label is a structural hook as well as a wrapper — Buckholt uses its presence to tell labelled and icon-only layouts apart, so it must not be omitted from a labelled button.

2. Danger modifier

Danger is a modifier rather than a fourth type. .btn-danger is added alongside a standard type, and the runtime pairs it with each one. Use it for destructive actions.

Secondary + danger
Ghost + danger
<button type="button" class="btn btn-secondary btn-danger"> <span class="button-label">Delete record</span> </button>

3. Sizes

.btn-sm for small, no modifier for default/medium, .btn-lg for large. Small suits confined layouts, large suits greater emphasis such as the end of a form. Runtime minimum heights are 32px, 40px and 48px.

4. Labelled buttons with icons

The canonical structure places a .btn-icon wrapper before .button-label. Buckholt trims 4px from the leading padding when an icon is the first child of a labelled button, and the icon inherits the label's colour and font size.

  • Icons are optional and should be used sparingly.
  • Icons sit to the left of the label — never after it.
  • The icon must relate directly to the action; do not repurpose a familiar icon.
  • Keep icon usage consistent across comparable labelled buttons in the same set.
  • Use the regular style unless the catalogue documents an icon as solid or brands.

5. Icon-only buttons

An icon-only button is a .btn containing .btn-icon and no .button-label. That absence is the actual runtime trigger — Buckholt selects these with .btn:not(:has(.button-label)) and squares them to 40px by default and 32px at .btn-sm.

  • Documented sizes are default/medium and small only, so no large icon-only button is shown.
  • Primary, secondary and ghost may all be used; primary and ghost are the common choices.
  • Use only where the icon is standardised and clearly recognisable, and use sparingly.
  • Prefer a toolbar pattern when several compact icon actions are needed.
  • Provide an accessible name, and a tooltip explaining the action is always required.

Accessibility treatment

The accessible name comes from aria-label on the button, and the tooltip uses the documented Bootstrap attributes — data-bs-toggle, data-bs-title, data-bs-placement and data-bs-trigger — initialised by the Bootstrap bundle at the end of this page. Hover or long-press any icon-only button below to see it.

An accessible name cannot use .button-label here, because adding that element would convert the control back into a normal labelled button at runtime.

6. Disabled states

Disabling uses the native disabled attribute — no aria-disabled substitute and no custom dimming. Buckholt keeps the resting colours and applies 65% opacity through --button-disabled-opacity, and removes interaction.

The disabled icon-only buttons keep their accessible names but carry no tooltip attributes, because Buckholt removes pointer events from disabled buttons and a hover tooltip could never fire.

7. Button sets

Two or more related buttons go inside .button-set. Buckholt binds set layout to the attribute selectors [class$=-set] and [class*="-set "] combined with [class|=button], so button-set must be the first class on the element — putting a utility class in front of it silently disables the set rules.

  • Default spacing is 8px, with 8px row spacing when the set wraps.
  • The primary button sits on the outer edge; secondary and ghost sit inside.
  • Group only contextually related actions, and never use two high-emphasis buttons in one set.
  • With more than three calls to action, ghost buttons are preferable to several secondary buttons.
  • Do not mix icon-only and labelled controls in the same set.
Standard set — full-page layout, primary on the outer edge
More than three actions — ghost preferred over repeated secondary
Consistent icon use across a set
Icon-only set — spacing tightens to 4px automatically

Buckholt narrows the gap with [class|=button]:has(.btn-icon):not(:has(.button-label)), so 4px applies only when the set is entirely icon-only. That is the same rule that enforces "do not mix icon-only and labelled controls in one set" — mixing them silently restores 8px spacing.

Contained layout — primary on the outer edge

Modals, data rows and repeat groups commonly right-align their actions. Buckholt documents the alignment behaviour but no Button-specific alignment class, so this example shows the documented ordering only and leaves alignment to the containing pattern.

8. Stacked and full-width button sets

Adding .button-set-stacked switches the set to a column and stretches every direct child button to full width. Row spacing stays at 8px. Short forms and small screens are the documented cases for full-width buttons.

9. States, focus and keyboard

These are native <button> elements, so they are keyboard operable and activate with Enter or Space. Tab through the row below to see Buckholt's own focus treatment; hover and active styling come from the same stylesheet. No state colour is hard-coded on this page.

Buckholt gives resting primary and secondary buttons a deliberate 3px bottom border (1px + 0.125rem) and returns it to 1px on focus and active. Ghost buttons use the normal 1px border throughout. This treatment is intentional and must not be overridden.

10. Notes for maintainers

Two small differences between the Button rules and the icon catalogue, reported rather than silently resolved. Neither blocked this page.

Note Detail
Save icon name differs components/button/rules.md gives the Save mapping as fa-regular fa-save. foundations/iconography/catalogue.md records Save as fa-regular fa-floppy-disk. These resolve to the same Font Awesome glyph, so nothing renders differently, but the catalogue is authoritative for icon naming and the two files should agree.
Print has no catalogue entry rules.md lists fa-regular fa-print among its verified common-action examples, but the 111-icon catalogue contains no Print entry. No print action is used on this page.
Tooltip trigger is hover only The documented tooltip pattern sets data-bs-trigger="hover", which means the tooltip does not appear on keyboard focus — Bootstrap's own default is hover focus. Keyboard and screen-reader users still get the action name from aria-label, so this page follows the documented value unchanged.
