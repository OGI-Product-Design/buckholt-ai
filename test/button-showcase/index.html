Danger — unresolved in the current sources

No danger button treatment can be rendered: the compiled CSS ships no danger button selector.

components/button.md and tokens.json both describe danger as "an override treatment layered onto primary, secondary and ghost", but neither names a class, and css/buckholt.css contains no button selector that consumes the danger action tokens. The tokens exist and are otherwise unused:

Token Value Documented role
--action-danger-01 #D7050C Resting
--action-danger-02 #AE0A09 Hover
--action-danger-03 #590407 Active
--action-danger-04 rgba(215, 5, 12, 0.1) Subtle background
--action-text-danger-01 #D7050C Danger label

Per design.md — "do not invent a missing source file or selector simply because the documentation describes a pattern" — no danger button is rendered and no one-off red button CSS has been added. The shared specification needs the real danger class name from _button.scss, after which this section can show filled (primary + danger), bordered (secondary + danger) and text-like (ghost + danger) examples at all three sizes.

components/button.md restricts icon-only buttons to the default and small sizes, and requires both an accessible text label and a tooltip. Buckholt ships no tooltip component in the compiled CSS, so the native title attribute provides the tooltip and .visually-hidden provides the accessible name. Note that these sets collapse to a 4px gap automatically, via Buckholt's :has(.btn-icon) rule.

Button sets

Set behaviour comes from Buckholt's generic [class*=-set][class|=button] rules. The |= matcher reads the whole class attribute, so button-set must be the first class on the element — putting a utility class in front of it silently disables the set rules.

Specification findings

Finding Detail
Danger has no selector Documented in components/button.md and tokens.json but absent from css/buckholt.css. Treated as unresolved above.
Small radius does not apply The spec states a 6px radius for .btn-sm. The compiled CSS sets --button-border-radius on .btn-sm and .btn-lg, but .btn reads --button-radius. The custom property never reaches the border-radius declaration, so small buttons render at 8px. This is a compiled CSS defect, not a markup error — it is reported rather than patched here.
.btn-combo missing Listed in components/button.md and tokens.json, but no .btn-combo selector exists in the compiled CSS. Not shown on this page.
.button-label has no implementation Used in the repository's documented markup and kept here for consistency, but the compiled CSS defines no rules for it. It is currently an inert hook.
No tooltip component Icon-only buttons are required to carry a tooltip, but the compiled CSS ships no tooltip selector. The native title attribute is used pending a Buckholt tooltip contract.
.btn-sm.btn-icon padding is overridden .btn-icon sets --button-padding-x to 8px, but .btn-sm is declared later and resets it to 12px, leaving a 6px content box inside a fixed 32px button. The icon is centred rather than clipped, so there is no visible impact today, but the two rules disagree.
Ghost shares carousel selectors .btn-ghost is grouped with .bh-carousel-control-prev/next, which also inherit .btn-icon sizing. Expected, but worth knowing when debugging.
